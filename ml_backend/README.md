# ML module for bankruptcy prediction

Базовая версия tabular-baseline-v1. CatBoost обучен на всех 247972 объектах TRAIN, 1249 деревьев. Локальная ROC-AUC 0.64661 относится к отдельному валидационному эксперименту; публичная оценка полной модели 0.65005. Проценты не проходили отдельную проверку калибровки. Не добавляйте собственные границы низкого/высокого риска без согласования.

## Подключение

Python 3.12, Linux/Windows с поддерживаемой платформой CatBoost. CUDA и видеокарта для inference не нужны. Установите зависимости из готового архива:

```bash
python -m pip install -r requirements.txt
```

Создавайте Predictor один раз при запуске backend. Пути ниже относительны к рабочей директории; в приложении задавайте абсолютные пути относительно файлов проекта.

```python
import json
from predictor import Predictor

predictor = Predictor("artifacts", thread_count=2)
records = json.loads(open("example_request.json", encoding="utf-8").read())
result = predictor.predict(records)
print(result)
```

Вход: непустой список плоских объектов. Каждый содержит все feature_0 ... feature_1366; значения — числа либо null. Порядок ключей не важен. index необязателен, строка или целое; без него в ответе index=null. word_count необязателен, строка частотного словаря либо null. ТЕКУЩАЯ МОДЕЛЬ НЕ ИСПОЛЬЗУЕТ word_count; оно зарезервировано для следующей версии. Не формируйте объяснения о влиянии текста на текущий прогноз. target во входе запрещён, как и неизвестные поля. Отсутствующие признаки отклоняются, null превращается в NaN, бесконечности после преобразования float32 также превращаются в NaN. Не стандартизируйте и не заполняйте признаки самостоятельно.

Ответ: список объектов {"index": исходный идентификатор или null, "target": вероятность положительного класса от 0 до 1}. Для процентов на экране умножьте target на 100; для вычислений храните исходное число. Формат ответа predictor.py — внутренний интерфейс библиотеки, HTTP-маршруты создаёт backend.

Файл example_request.json содержит реальные первые 3 объекта TEST, example_response.json — проверенные ответы этой модели. prepare_backend.py при сборке сопоставляет их с отправленным CSV.

## Поиск по index

Модель не восстанавливает признаки по идентификатору. Разработчик может использовать собственное хранилище либо собрать прилагаемую SQLite-базу из общих файлов TRAIN и TEST. Команда выполняется один раз, не внутри HTTP-запроса:

```bash
python build_lookup.py --data-dir /path/to/data --output lookup.sqlite
```

Требуется примерно 2 ГБ места для базы плюс запас. Полные CSV не загружаются в память. target не сохраняется, тексты пока не сохраняются. База не включена в архив, её строит команда там, где доступны исходные CSV. Конфликтующие index останавливают сборку. Не прерывайте процесс; после сбоя удалите только незавершённый lookup.building.sqlite перед повтором.

```python
predictor = Predictor("artifacts", lookup_path="lookup.sqlite")
result = predictor.predict_by_index("194357")
```

Ответ этого метода — один объект {index, target}. Для CSV с новыми объектами backend читает строки, преобразует числовые значения и пустые значения в числа/null, затем вызывает predict списками. Не считывайте CSV через json.loads. Для крупных файлов используйте порции, например по 1000 объектов.

ValueError означает ошибку входа (например HTTP 422), KeyError — неизвестный index (404). Остальные ошибки конфигурации/модели — серверные; логируйте детали, пользователю возвращайте нейтральную ошибку. Ограничения размера загрузок и числа одновременных запросов задаёт backend с учётом ресурсов сервера. Число потоков CPU на один вызов — thread_count.

## Обновления

Текущая версия использует только табличные признаки. Следующий комплект может добавить текстовую предобработку и модели: обновлять надо весь комплект кода, артефактов и зависимостей. Планируется сохранить методы predict и predict_by_index, но текстовое хранилище потребуется расширить. Не встраивайте прямой вызов model.cbm в backend — используйте Predictor.

Только этот готовый ZIP содержит модель и подходит для передачи.
